# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Exact Geometry Dash replica for RL training (sim-to-real: train in the replica, deploy to the real game via a Geode mod). Roadmap, physics-extraction strategy, and the trace-verification loop are in @gd-replica-notes.md — read it before making design decisions.

## Build

MSYS2 UCRT64 toolchain (g++/cmake/ninja on PATH):

```
cmake -S . -B build -G Ninja && cmake --build build
```

- **Do not remove `-static` from CMakeLists.txt.** This machine's MinGW ld (binutils 2.43.1) crashes with a silent "ld returned 116 exit status" when linking C++ exception code against shared runtimes. If a new target fails with exit 116, static linking is the fix.
- raylib and zlib come from MSYS2 packages, not FetchContent.

## Viewer GUI (src/viewer)

- raylib window + a Dear ImGui panel on the right (rlImGui backend). **Deps are FetchContent'd at configure time** (`build/_deps`): ImGui `v1.92.7`, rlImGui tag `Raylib_5_5` (its `main` targets raylib 6.0 — do not bump one without the other; the 5.5 tag needs ImGui >= 1.92), nlohmann/json 3.11.3. First configure needs network; `-DVIEWER_VENDORED_DEPS=<dir>` with `imgui/`, `rlImGui/`, `json/` checkouts builds offline.
- Layout: the game viewport is `App::viewW x viewH` anchored at (0,0); every camera/background site uses `viewW(app)/viewH(app)`, never `GetScreenWidth()`. Mode input goes through `viewer/input.hpp` wrappers (gated on ImGui capture) — never raw `IsKeyPressed` in a mode. Modes draw their own controls in `Mode::drawPanel`; cross-tab requests go through `App::commands` (consumed in `main.cpp`).
- The panel launches `python -u -m gdrl.*` (cwd `python/`, absolute paths) and the tool exes via `viewer/jobs.cpp` (Win32 pipe + Job Object, children die with the viewer). `jobs.cpp`/`paths.cpp` include windows.h and must never include raylib.h.
- **Train-tab defaults mirror `PPOConfig`/`train.py`** (`Gui::TrainForm` in `gui.hpp`); change them in both places. Only non-default flags are emitted.
- **Graceful stop**: the GUI writes `runs/<name>/STOP`; `train.py` checks it once per update, saves `ckpt_latest.pt`, prints `stopped: ...` and exits 0 (also on Ctrl-C). Stale STOP files are unlinked at startup.
- Pipeline: a `| det ... WIN` line auto-launches `gdrl.eval` on `ckpt_best_det.pt` (once, plus a final eval at exit); Deploy is always a confirmed click.
- **The trainer's `upd` log line is parsed by a regex** (`Gui::pollPipelines`, `gui.cpp`) — a field added to the print in `train.py` needs the regex + `TrainStatus` updated too. `live.bin` is v2 (`python/gdrl/live.py`; header stays 40 bytes): `sps`/`samples_s` are the *last completed update's* rates, identical to the log line — never publish a mid-rollout running rate again (it excluded `t_update`/`t_sil` and read ~6x high).
- Frame pacing is driven from `main.cpp` via `Mode::targetFps()` (Play = 240, everything else 60), halved to 30 while a panel-launched python job runs and the window is unfocused. Don't call `SetTargetFPS` inside modes. The viewer costs the trainer ~7% decisions/s when open on the Training view at 60 FPS (GPU-side contention: `t_update`/`t_roll_gpu`), ~0% closed. **`App::livePreview`** (checkbox "Live preview" in the Train tab and the Training view's panel, pref `live_preview`) turns the preview off entirely: no `live.bin` polling, no world/ghost draw, 30 FPS (15 unfocused) — measured at parity with the viewer closed; the Train-tab stats/plots still update from the stdout scrape.
- **`config.json` `end_x` is the *effective* end** (a full-level run records the level's natural end); `end_x_arg` is the requested `--end-x` (-1 = full). `prefillResume` and the Runs table's truncation marker (`*`, orange) use `end_x_arg`; legacy configs infer it by comparing `end_x` to the level's natural end (`runs.cpp: naturalLevelEnd`). Never prefill the form from `end_x` � that's how Back On Track's 25045 became a hard cutoff for Polargeist runs.
- Prefs persist in `<repo>/viewer_prefs.ini` (gitignored); repo root is found from the exe path. Automated captures: `viewer --shot out.png [--panel] [--tab N]` (0 View .. 4 Jobs; `--shot` never persists prefs). "Rebuild incl. viewer" renames the running `viewer.exe` to `.old` first (deleted on next start).

## Architecture rules

- `gdcore` (src/core) must stay free of rendering dependencies — it becomes the headless training sim. Rendering-only concerns (e.g., the object-id → shape table) live in the viewer.
- The viewer's shape table is presentation-only; never treat it as hitbox/collision data. Hitboxes come later from the binary (see notes).
- Future sim work: fixed timestep only, never variable delta time (determinism requirement, see notes).

## RL env contract (src/env + python/gdrl)

- **Observation versioning** (`src/env/obs.hpp`): the scalar block and grid layout are frozen; changes are additive-only and bump `kObsVersion` (checked by `python/gdrl/env.py` at DLL load; `model.load_model_state` migrates older checkpoints by zero-padding the appended scalars). v4 = scalars 0–25 (17 gravity flag, 18–23 next two specials incl. rings, 24 ring pressable, 25 buffer armed); changing the grid y-band is an obs v5 decision. `obs.hpp` will be `#include`d verbatim by the Geode mod — compile-time constants only, no runtime normalization.
- **Speed portals later change an input, not the network**: per-tick `dx` is already an obs scalar and a `buildObs` parameter.
- **Env stepping is parallel and bit-deterministic**: `$GDENV_THREADS` total threads (1 = exact serial fallback), default `hardware_concurrency()-1`. After touching the env layer, run `./build/env_check det` AND `python -m gdrl.selftest` (from `python/`; serial-vs-threaded byte-identity).
- **Regression bar for RL changes**: a default `python -m gdrl.train` run must still beat Stereo Madness (deterministic `det ... WIN` line / `wins.gdtrace`), and `python -m gdrl.eval runs/<name>/ckpt_best_det.pt` must write a `solution.json`. Don't shrink `--updates` for the check — it compresses the lr/entropy anneal and changes the learning trajectory.
- **Exploration is position-dependent** (`train.py --explore-margin/--mastered-bound`, model.py per-sample `bound`): the logit-bound-4 floor (~1.8%/decision) applies only at x >= latest det_x - 600; the mastered prefix samples at bound 8. Measured on Polargeist: a full run is ~3300 decisions, and the winning policy sampled from x=0 at bound 4 reached the last third 0.1% of the time (43% at bound 8), so a blanket floor starves the frontier of from-start rollouts. Each sample's bound is stored in the rollout buffer and re-applied in `evaluate` (ratios stay exact); `GraphedAct.bound` is a static graph input. **Respawned episodes are frontier bursts** (`--burst 1000`): truncated (V-bootstrapped) 1000 units past their spawn and respawned again, so wall attempts per update go from tens to hundreds; `--frontier-respawn 0.4` of respawns start in the 700 units before the latest det_x (the pass-rate 'learnable' filter skips the hardest wall by construction), and `--mastered-ent 0.1` scales the entropy bonus down in the mastered zone (advantages there are ~0, so a full bonus erodes the prefix). Measured on Polargeist: det WIN at update 289 (v1) / 269 (v2) vs 719 before; Stereo Madness still wins (reg-p4/p5). Polish also triggers on the det eval reaching `--polish-det` (default 1.0 = det win); the stochastic-wins gate never fires on long levels. `log.csv` has a `frac_explore` column and the log line an `xpl` field (fraction of rollout samples at the floor).
- **Planner-in-the-loop (added 2026-09-03 after `runs/level9-2` sat 500+ updates at Cycles x 19681)**: `src/env/solve.hpp` is a macro-action BFS in the policy's own action space (branches on `EnvInstance::step` decisions, tick-bucketed, dedup by the tools/solve.cpp key); `gdenv_solve` runs it on the DLL pool from state blobs, `gdenv_trace_states` snapshots blobs along a from-start hold sequence, and `gdenv_replay` now takes optional start blobs and returns `final_obs`/`ends` so a SEGMENT replays (env.py `solve`/`trace_states`/`replay`). train.py `WallSolver` (background thread, own handle): after every non-winning det eval it solves from the det run's OWN states in `[det_x - --solve-back, det_x - 50]` (7 starts + 3 bank states) to `det_x + --solve-reach`; found segments go to `sil_buf.demos` (cap 64, `--sil-demos 4` replayed per SIL update with a fixed 25% minibatch share, alive-ending streams bootstrap V(final obs)) and their states into the respawn bank; `--solve-back` doubles on total failure (up to 8x). Measured at the 19681 wall: 6/7 starts solve in 0.08 s total, the policy there had p(flip)=0.982 where ~15 straight no-flips were needed. `--anchor-coef 0.1` / `--anchor-margin 2` = a hinge `relu(margin - sign(a)*logit)` on the BEST det run's decisions inside the mastered zone (x < best det_x - margin) in the same SIL pass: level9-2's det_x fell 12777 -> 2490 twice (trunk drift under frontier updates, nothing anchored the prefix), and a plain -logpi anchor still let a run die at x 5547 after reaching 22112 because the log-likelihood gradient is ~0 at p=0.999 — the hinge holds a margin preventively and is zero where it holds. The mastered zone is keyed to `max(latest, best)` det_x (one flipped prefix decision used to turn the whole level into the explore zone: xpl 0.00 -> 0.76, x65 prefix deaths/update). `--det-rollback 0.5` restores `ckpt_best_det.pt` after 2 consecutive det evals below that fraction of best_det_x (or one below 0.3x), armed only once best det_x >= half the level (early det evals swing 4k-12k normally; a rollback at update 72 cost the first Stereo Madness regression 60 updates). `--solve-stall 3` = the planner fires only after 3 det evals without a new best (demos after every eval slowed Stereo Madness to det WIN 179; with the gate it is 119 = the reg-p4/p5 baselines and the planner never fires on level 1: `runs/reg-p7-planner`). `--solve-nodes 2000000` because a ship section at 4-tick decisions needs ~1.3M nodes per 800 units (400k failed 0/7 at Cycles x 16728). `--wall-solve 0` = pure exploration as before. **Result: `runs/wall-test2` resumed from level9-2's ckpt_best_det (update 1830, stuck at 19681 for 500+ updates) reached det 22112 by update 2009 and `det WIN` at update 2059, no collapses; `gdrl.eval` wrote its solution.json (18684 ticks). `runs/level9-3` = Cycles FROM SCRATCH with the final stack: det WIN at update 1909 (51 min wall), deployed 2026-09-03 and replayed by the mod = traces/session19, a full real-game completion, all 18685 ticks bit-exact in both recordings, 0 hold mismatches — the first policy-trained Cycles solution to beat the real level.** Its log shows the next RL problem: 990 of the 1909 updates (459-1449) were ONE wall at x 12777, a ball corridor where the argmax policy never flipped from the ceiling to the floor although the window is ~19 decisions wide, the planner solved it 7/7 in 0.35 s (demos in the pool the whole time, `sil_loss` climbing 0.5 -> 1.8) and the best stochastic rollout crossed it in 879/991 updates on the 1.8% floor alone. The head was SATURATED: the winning checkpoint's raw (pre-tanh) hold logits are -20..-33 across that corridor and |raw| > 8 on half of all decisions (> 12 on 43%), so with `logit = 4*tanh(raw/4)` the gradient factor is 1-tanh^2(raw/4) ~ 2.5e-5 — PPO, SIL demos and the entropy bonus all vanish there (the same mechanism as level9-2's p=0.982 wall, opposite sign). Fix (2026-09-03): **`--logit-leak 0.1`** (model.py `logit_leak`): the bound's backward is floored at `d logit/d raw = max(1 - tanh^2(raw/L), leak)` via a detached straight-through term, so forward values, sampling, PPO ratios, checkpoints and inference are untouched (eval/deploy build the model with leak 0) and a wrong saturated decision keeps >= 10% of an unsaturated one's gradient. A raw-magnitude penalty alone would not help at bound 4 and would cost the mastered zone's p=0.9997 (bound 8 needs |raw| >= 20). Measured: `runs/reg-p8-leak` (level 1) det WIN at 119 = baseline; `runs/level9-4` (Cycles from scratch, stdout in `train.log`) det WIN at update 1759 / 36 min vs 1909 / 42 min — the corridor stall shrank from 101 det evals to 47 (both corridor walls fell in one step), but the prefix got fragile: 12 det evals below half the best (vs 1), 7 det rollbacks (all prefix deaths at x 537-6627, all recovered), a new 34-eval stall in the ship section at x 15927, and mean rollout entropy 0.05 vs 0.15. Three of the seven prefix deaths came within ~60 updates of the planner solving a PREFIX segment after the previous prefix death (base rate ~1 per 400 updates): BFS demos there teach a different route than the anchored det run, and with the leak the policy can actually follow them. Hence (same day) the planner only fires when the det death is at the frontier (`dx_ >= max(best, anchor) det_x - explore_margin`) and `SILBuffer.prune_demos` drops demos whose reach is inside the mastered zone; validation runs `runs/reg-p9-gate` / `runs/level9-5`. The trainer's log line gains `demos N` and a `WALL k/n demos from a-b -> t` field; checkpoints carry `anchor_holds`/`anchor_x`/`solve_back` and the demo pool.
- Hyperparameter defaults live in `PPOConfig` (`python/gdrl/ppo.py`); the train.py CLI mirrors them — never introduce a second default (the viewer's Train tab is a third mirror, `Gui::TrainForm`; keep it in sync).
- **Performance contract**: trunks run under bf16 autocast with channels_last conv tensors (`--amp bf16`, default; `--amp none` = fp32); heads, logit bound and losses stay fp32 — keep it that way (bf16 logits inject noise into PPO ratios). The Bernoulli math is closed-form (`model.py`), not `torch.distributions`. `--compile` is opt-in and needs Triton (`pip install triton-windows`). Det eval runs off-thread (`DetEvaluator`); SIL replay is one DLL call (`gdenv_replay`). Before/after any perf change run `python -m gdrl.bench --compare <baseline.json>` (from `python/`) and check the per-phase `t_rollout/t_update/t_sil/t_det_wait/t_ckpt` columns in `log.csv`. **`ticks/s` is not a throughput metric**: ticks per decision falls ~23 → ~10 as the policy stops hopping (a ground hop is one decision of ~104 ticks) and again in POLISH (longer episodes, `target_kl` early stop no longer fires at lr ≤ 1e-4); compare `samples_s` (log.csv) / `dec/s` (log line, panel) across runs and phases instead.

- **Sim-to-real loop**: `python -m gdrl.eval runs/<name>/ckpt_best_det.pt` → `python -m gdrl.deploy runs/<name>` (re-verifies the raw holds win via `env_check run`, then installs `<level_id>.json` into the mod's `solutions/`) → play the level in GD (normal mode, no start pos, click-between-frames off) → the mod writes `traces/attempt_NNNN.csv` + `result_NNNN.json` in its save dir → `build/trace_check.exe <that csv>` names the first divergent tick on a desync; `python -m gdrl.deploy --check-trace <csv> runs/<name>` asserts the recorded holds equal the solution.
- **Tick contract**: real tick t = t-th `GJBaseGameLayer::processCommands` after `PlayLayer::resetLevel` (trace row t). **Sim tick t = real tick t+1** — the real game's tick 0 is a pre-movement input tick (row 0 has x=0) while sim step 0 already moves the player. So the replayer injects `holds[t-1]` at real tick t, `trace_check` applies row i's hold to sim step i-1, and `deploy --check-trace` compares the same way. Getting this wrong = one-tick-early jumps that clip blocks (first real-game run died at 54.8% this way). `solution.json` ranges are `[start,end)` in sim ticks; `env_check run` ranges are inclusive sim ticks (deploy.py converts).
- Raw addresses in both mods are GD **2.2081 Windows** only.
