### setupSpriteSize (2026-09-04)
`GameObject::setupSpriteSize` 0x1401a36a0 (byte table 0x1401a3fec / jump table 0x1401a3f2c, id−1) is called at the end of `customSetup` (0x1401946af) for every non-decoration object and overwrites m_width/m_height with a per-id constant pair. Decoded for every classic id it reproduces every objects.csv size (9 → 30x27, 61 → 30x18, 12/13/47/111 → 34x86, 88 → 44x85, 98 → 40x40, 99/101 → 31x90, 103 → 20x19, 140 → 25x5, 39/40 → 30x14, 62/65/66/68 → 30x16; ids without a case keep commonSetup's sprite-rect copy). This is why the dump's w/h are integers while a sawblade's radius (computed inside its customSetup case, before the table) still carries the -uhd trimmed rect (39.25). Use it for rect sizes before a dump exists.

### Cached collision rect on size-portal ticks (2026-09-04)
`GameObject::getObjectRect()` returns the rect cached at +0x358 unless `m_isObjectRectDirty` (+0x368) is set; only position writes (`setObjectRectDirty` 0x140137c50) set it, `togglePlayerScale` does not. So on the tick a size portal fires, collision tests keep the previous size until a snap's `setPosition` rebuilds the rect, and `collidedWithObjectInternal` re-tests the current rect against each object (0x140392442) before its blocks. Session24 tick 3016: a ship on a block enters the mini portal and is re-landed at +15 (the second block no longer overlaps the shrunk box); tick 3285: a mini ship enters the normal portal, the first block re-lands it at +9, the rebuilt 30-box then overlaps the neighbouring block and re-lands at +15. Sim: `PlayerState::rectMini` (refreshed at every position write), per-contact overlap re-test in `stepFlyingSolids`, `half2` for the cube's pattern re-test. Clutterfunk's nine portals never hit a solid on the portal tick, so this was invisible before.

### UFO mode (Theory of Everything, 2026-09-04)
m_isBird +0x9ba. A flying mode in every engine list (updateJump branch 0x14038c701, 6-unit snap window, both flying solid blocks, playerTouchedRing's no-contact-ring gate, pushButton's no-ground-jump gate, band group). Boost: when m_hasJustHeld && m_isHolding, updateJump consumes the press and sets yvel = round3(7.0) (mini: f32(8 × 0.85) = 6.8) only if that is faster "up" than the current yvel (normal: v > yvel; flipped: yvel > −v); pushButton does NOT call updateJump for the bird, so a click boosts on the next tick and a hold boosts once (release + press for another). Gravity the same tick, after the boost: yvel −= f32(f32(f32(sign·A)·factor)·0.5)/div with factor = playerIsFallingBugged ? 0.8 : 1.2 (no hold term), i.e. −0.086 slow / −0.129 fast per tick; clamps [−6.4, 8] (flipped mirrored, mini ÷0.85) shared with the ship. Band 300 re-centered on the portal; ceiling hitGround only if yvel > 0, floor hitGround unconditionally (the yvel < 0 gate at 0x1402140f1 is ship/swing only). toggleBirdMode halves yvel raw + ungrounds on every flag change; the UFO portal case runs switchedToMode(19) (toggleFlyMode(0)) first, the ship portal case switchedToMode(5) (toggleBirdMode(0)) first, so ship ↔ UFO is ×0.25. Rings only via pushButton (pink ×0.42), pads: pink bumpMod 0.4, no 0.6 tail. Sim: `PlayerState::bird`, `ufo::`, `flying()`, `stepBirdBand`; obs scalar 3 = +0.5 / scalar 7 = −0.5 (values only, still v5); macro action = one TAP (release-if-held, press, releases) per `ticksPerAction`; trace `mode` column 3 (both mods rebuilt 2026-09-04); solve keys bit 17.

### m_isOnGround fall-path clear (2026-09-01)
Byte +0x9c1 is m_isOnGround. It is cleared in `updateJump`'s fall path (helper 0x39a430), not at the head of `checkCollisions`: normal gravity when pre-gravity yvel < f32(1.92), flipped when > 1.92. So a flipped cube walking off a block stays jumpable 9 ticks. First BAB deploy died at 78% because the sim treated that press as an air no-op.

### Ball mode (Cycles)
Runs updateJump's cube branch with gravity ×0.6f, the same ±15 clamp and 2·m_gravity falling test. "Jump" = cube jump (±11.18) then `flipGravity(!upsideDown)` (yvel ×0.5 raw, ungrounded) then yvel ×0.6f raw → a 3.354 kick toward the new gravity, and it clears m_isHolding, so a held button flips once. Hence `PlayerState::inputHeld` (physical button) is split from `holding` (m_isHolding). Rings: ring velocity then ×0.7f raw, m_isHolding = 0, no flip (pink 0.77). Pads: propell then ×0.6f raw (pink bumpMod 0.7). Band: ceiling = getGroundHeightForMode(16) = 240; ceiling snap calls hitGround only if yvel > 0, floor snap always. Solids: the ship's two-block logic with the cube's 10-unit window; no landing x snap. Ball↔cube portals keep yvel/onGround; ship↔anything halves yvel and ungrounds. Also modeled, never trace-hit: the 0.1 s post-flip inner-box escape (`checkDeaths` takes prevY). Trace `ship` column is now the mode (0 cube, 1 ship, 2 ball).

### Vertical bound (2026-09-02)
`checkCollisions` 0x140213bfe flags y > `m_maxGameplayY` (+0x36a8; 2790 for classic levels, `updateMaxGameplayY` 0x23aec0) and kills on the second consecutive flagged tick. Found because `runs/level9-1` "won" by flying a flipped cube at y ≈ 25000; the real game killed it at tick 2838 (session17).

### Portal-centered flying band (2026-09-03)
`animateInDualGroundNew` 0x213370 sets center = max(90, floorf((portal.y − H/2)/30)·30) + H/2, H = 300 ship / 240 ball; band = center ∓ H/2, re-centered on every activatable ship/ball portal contact. Every level 1–9 portal yields floor 90; xStep's ball 47@18405 gives [180,420] and ship 13@23025 gives [150,450]. Now `Portal::bandFloor` / `PlayerState::bandFloor`. `runs/level10-1` sat 1000 updates at 84% on the fictional [90,330] band. Trace logger logs `bandmin,bandmax,bandcenter,bandh,...`.

### Circle hazards (Clutterfunk sawblades)
88/89/98 are EnhancedGameObjects; customSetup case 0x1401a5bd9 sets type 2 and `m_objectRadius` +0x38c = 32.3 (88, constant) / m_width × 0.36 (89, 60 → 21.6) / m_width × 0.3 (98, **39.25 → 11.775**: m_width at that moment is the -uhd sheet's trimmed rect 157 px / 4; the dump's later w column says 40, so always read the `radius` column). checkCollisions' hazard loop uses `playerCircleCollision` 0x211df0 for any radius > 0; with `m_fixRadiusCollision` (LevelSettingsObject +0x1cf, a 2.2 option, clear in official levels) the test is: player outer rect contains the center (inclusive) OR a rect corner is strictly inside the circle (float distance). Not a true circle–rect test. `updateIsOriented` skips the oriented box when radius > 0, so a hit is a death directly. Sim: `Box::radius/cx/cy`, `circleHitsPlayer`.

## Sim solver
`build/solve.exe <level.txt> [solution.json]` = sim-only BFS, ~1–2 min/level, deploy-compatible output; existence proofs in `runs/solve_*` (discard `runs/solve_10`, solved on the old band). Its holds are per-tick and not reproducible by `GdVecEnv.replay`; use `env_check run`. The per-tick population cap (16384, uint16 history indices) is thinned **stratified by y** since 2026-09-04: the old smallest-hash cut killed single-continuation lineages (a UFO that never boosts) and dead-ended Theory of Everything at x 17260 although the sim passes. `GD_SOLVE_DEBUG=<from>:<to>` prints the population size and y range per tick; a dead end prints the surviving states.

## RL history

- **Macro actions** were the original learning fix; **tanh-bounded logits** fixed saturation walls; split trunks fixed collapses; CNN + polish closed the det gap.
- **Position-dependent exploration** (2026-09-01, Polargeist det WIN 719 → 269): the 1.8% logit-bound-4 floor only at x ≥ det_x − `--explore-margin`; mastered prefix samples at bound 8 (bound stored per sample, re-applied in `evaluate`). `--burst 1000` frontier bursts, `--frontier-respawn 0.4`, `--mastered-ent 0.1`, polish on `--polish-det`.
- **Planner-in-the-loop** (2026-09-03, `runs/level9-2` stuck 500+ updates at Cycles x 19681 with p(flip) = 0.982 where 15 no-flips were needed): `src/env/solve.hpp` macro BFS in the policy's action space from the det run's own states (`WallSolver`, `--solve-back/--solve-reach/--solve-nodes 2000000`), demos into SIL (`--sil-demos 4`, 25% minibatch share) and the respawn bank. `--anchor-coef 0.1 --anchor-margin 2` hinge on the best det run's mastered-zone decisions (prefix drift had dropped det_x 12777 → 2490). `--det-rollback 0.5` restores `ckpt_best_det.pt` after 2 bad det evals once best ≥ half the level. `--solve-stall 3` keeps the planner off Stereo Madness (det WIN stays 119). Result: level9-3 from scratch beat real Cycles (session19).
- **Leaky logit bound** (`--logit-leak 0.1`): level9-3 lost 990 updates at x 12777 because raw logits were −20..−33 (gradient factor ~2.5e-5 through the tanh bound). Backward floored via a straight-through term; forward unchanged (eval/deploy use leak 0). Cycles det WIN 1759 vs 1909, but the prefix got fragile (7 rollbacks), so the planner now fires only for frontier deaths and `prune_demos` drops mastered-zone demos.
- **Poisoned runs**: any run trained before a sim fix that changed reachable states (level9-1 sky states, level10-1 fictional band) must restart, not `--resume`.
- **Stitched training** (2026-09-04, `--stitch`, default on): `runs/level12-1` (1309 updates) and `level12-2` (742) both stalled in Theory of Everything's UFO spike-column corridor (x 16950–18570, det deaths cycling 16953/17516/18086/18476/18568). Diagnosis: the argmax was a bang-bang "tap when y < ~1020" rule 4 units short at the 17511 column; the planner's demos (57, reaching 18316) fixed it with ONE tap a macro step earlier (x 17392), but the policy's p there was 0.02 (raw logit −8..−15) at update 519 and still 0.02 at 742. The 3300-decision from-x=0 prefix ate ~95% of the rollout (frac_explore 0.03–0.08, ~0.3 useful samples/update at the wall), SIL's 4 demos/update were a handful of rows in a 4096-row mean, det rollbacks reset the weights 4×, and offline demo-BC (which did move p to 0.9 in 300 steps) flipped look-alike prefix decisions. Fix: the best det run's holds are a certificate; episodes and det evals start from its state `--stitch-back` (600) before its end, a further det run extends it, the frontier follows. Removes prefix relearning, prefix fragility and the anchor BC's job; SIL stores (suffix, spawn blob); traces/wins/`solution.json` remain full holds via each episode's `prefix_ticks`. Result: `runs/level12-2` resumed at update 742 under stitching went 17516 → 19526 in 130 updates (the corridor that held for 220 + 1309 updates), det WIN at update 1622 (19683 ticks), and the deployed solution completed Theory of Everything in the real game (`traces/session25`, 2026-09-05: 19683 gameplay ticks bit-exact in both mods, 0 hold mismatches, first policy completion of a UFO level).
